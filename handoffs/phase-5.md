Status: Stage: Done | Round: 8 (reopened after Done) | Updated: 2026-11-05 09:00

## For Tim
This phase builds everything needed before you spend your first money. A neutral "judge" (a Mistral AI) will read every important choice a player makes and label it, write a short summary of each game day and a profile of each player every game week, and flag betrayals, deaths and new beliefs. New measures compare what players say they value with what they actually do. Then come your tools: `calibrate` (measures what each AI really costs and evens out how hard they think), `judge-check` (a few test judge calls), the pilot setup (all four players on cheap AIs for 3 game weeks), `analyze` (a report on a finished run with suggested setting changes) and `launch-check` (a final safety check before the real run).
Two coders share the work: one builds the parts that run inside the game (the judge, the money safety, the real AI connections), the other builds your commands and the screen changes. Codex found several real money-safety problems that I adopted: the spending limit could be slightly underestimated, a crash at the wrong moment could leave a paid call uncounted, and the first real calls to OpenAI and Mistral would have failed. Anything that spends money will ask you to type "yes" first, so no agent can ever spend by accident.
You are approving the plan below. Nothing is spent in this phase; you run the paid steps yourself afterwards.

- `measure/calibrate.py: run_calibration(config, adapters, max_dollars, out_dir, dry_run) -> CalibrationReport` with the AC-5 fields: dry_run, complete, matched, versions, settings, thinking_tokens_by_model, cost_per_slow_decision, cost_per_hooked_decision, cost_per_game_week, weeks_per_100, reaches_week_7, cheap_seat_week_costs (per provider) and cheap_seat_week_cost (their maximum), pilot_cost, warnings. Calls go through one broker and ledger on `runs/calibration/<session>/calls.db`; report at `runs/calibration/report.md` plus `result.json`. Each sample call runs `repeats` times on each of the four mains (slow and hooked), each helper (noticer, advisor, fast, and slow/hooked main for the cheap estimate) and the judge (2 full, 1 short). Search: per main role the median thinking tokens over its slow+hooked main samples; matched when max/min <= 1.25 (all positive); else move the highest or lowest role one ladder step toward the others, keep the closest tested setting, repeat up to max_rounds or until matched, the ladder ends or the limit is near. None/zero thinking counts -> unmatched with a warning. Examples: medians [1000, 1050, 1100, 1200] -> 1.2 matched; [1000, 1000, 1000, 1500] -> 1.5 unmatched.
- Cost model (unit costs are means of the logged calls, including retries): per player p: slow_p = noticer + advisor + main_slow; seat_week_p = 7 x (14 x slow_p + 6 x hooked_p + 20 x fast_p) + reflection_cost_factor x main_slow_p; judge_week = 7 x 4 x (14 + 6 + 2) x judge_label + (7 + 4) x summary_cost_factor x judge_label (judge_label = mean of the judge samples); cost_per_game_week = sum of seat_week_p + judge_week; weeks_per_100 = 100 / cost_per_game_week; reaches_week_7 = run.toml spend_cap_usd >= 7 x cost_per_game_week; cheap_seat_week_p = the same seat formula with the main samples run on player p's helper + judge_week / 4; pilot_cost = pilot_weeks x sum of the four cheap_seat_week_p x (1 + safety_share). Example: slow 0.03, hooked 0.02, fast 0.001, main_slow 0.025 -> seat_week = 7 x (0.42 + 0.12 + 0.02) + 0.05 = 3.97.
