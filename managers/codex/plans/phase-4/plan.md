## Summary
Build the complete minds behind a fake-only runtime, with real provider adapters exercised only through injected SDK mocks.
Collect all eligible decisions before asking anyone; send independent calls concurrently and apply results in deterministic order.
Journal requests/replies before applying them, reserve maximum call costs before dispatch, and reuse journaled replies during verified recovery.
Keep private simulation truth outside every prompt; persist complete cognitive state separately from the existing world knowledge book.
Use two coders with frozen shared contracts: infrastructure/integration and cognition/presentation. Deliver in slices with offline evidence for AC-1..24.

`Usage.input_tokens` is uncached input; `Usage.output_tokens` is normalized total billable output including thinking exactly once (Google output+thought if disjoint). Adapter normalization explicitly subtracts cached reads/writes from provider aggregate input where that aggregate includes them; Anthropic input already excludes both. Noncached rates are the conservative reservation basis; reserve a provable maximum input bound plus configured total output/thinking bound at the highest applicable pinned tariff, then settle actual usage. If a provider cannot provide safe bounds, pause before dispatch rather than guess. Retries reserve again; all concurrently outstanding reservations count. Allocate wave slots/reservations in canonical key order, then send concurrently; Noticer -> Advisor -> main dependency order holds within each slow decision. Cache hits are never assumed in admission bounds. Cache-write tariff may exceed input tariff: bound with max(input,cache_write) for every possible written token, not input rate alone. All refused/invalid calls with returned usage are charged, unknown billing retains its reservation/unresolved state.

Journal protocol: persist `status=pending` intent with reserved bound before dispatch, then persist exact response/usage/status/cost and spend once as soon as it arrives, before world mutation. SQLite stays on its creating thread. Derive natural uniqueness from key lookups under the existing single writer lock; no new tables/SQL schema version. Physical attempts each have their own key/row. Reuse all stored terminal attempts (including invalid/refusal/errors) and retry sequence without network, retry waits or extra spend during replay. Reply-recorded/tick-uncommitted crash needs a read-through journal even beyond current events tail; otherwise existing recovery attaches too early and resends. Recovery verifies old committed event tail while suppressing all derived-table inserts; then a normal regenerated uncommitted tick can reuse any stored replies and commit exactly once. Never re-add ledger costs from replay; attach uses existing SUM(spend.cost_usd).

For a cap/outage during a partially decided tick: roll back in-memory world/RNG/controllers to the last complete tick boundary, retain durable call journal/reservations, save that coherent boundary and pause. On resume rerun that tick from the boundary using completed replies; unresolved intent remains paused. Reserve and journal no-attempt budget decisions consistently so retries cannot cause nondeterministic selection. No snapshot is ever taken with a half-turn or pending dependent call. Lost response after provider processing cannot be guaranteed exactly-once across arbitrary real crashes; pending-unknown pause avoids automatic duplicate charging, and P4 tests prove persisted-reply reuse only.

Pause request stops NEW logical decisions/ticks, but must allow an already-started Noticer -> Advisor -> main chain and its required retries to drain; otherwise no action exists to apply. A cap/outage can interrupt this drain and invokes the complete-boundary rollback above. Fake/read-only view may replay already stored AI data but must refuse beyond-journal AI advancement or use explicitly isolated fake projection, never initialize live clients or accrue simulated paid costs.
