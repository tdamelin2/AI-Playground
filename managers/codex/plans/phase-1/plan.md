## Summary
Build the complete no-player island on one deterministic, pygame-free minute engine.
Save exact JSON checkpoints, named random states and event watermarks in an eight-table SQLite schema established now.
Use sparse, configurable ecological schedules while preserving every minute and season boundary.
Generate one complete home template, rotate it four ways, and guarantee centre/home/landmark connectivity.
Resolve all prescribed dependencies on Python 3.13 Windows; application SDK imports wait until Phase 4.
Keep the observer read-only; a session controller owns ticking, persistence and live pacing.
Audit the complete asset manifest eagerly, recolour actual white Kenney artwork black and use binary overlays.
No existing game code was found under src/; this is a foundation plan, not an implementation audit.
All five ideas are included; the three Maybe conditions are resolved explicitly below for Claude's merge.

Detailed contract and implementation order:
1. A establishes config/state/event types and packaging; B inventories assets in parallel. No alternate package/dependency manifest from B.
2. Engine interfaces: create_world(config, streams) -> WorldState; step(state, config, streams) -> list[Event]; pathfind(grid, start, goal, terrain_costs) -> list[Position] | None. step mutates state exactly once from tick t to t+1 and emits ordered events stamped t+1. Tick 0 is initialized day 1/spring/week 1. Any initialization events are stamped 0. Event is a Pydantic discriminated union of concrete payload models with tick/type/payload; arbitrary unvalidated payload dictionaries are insufficient.
3. WorldFrame is frozen and contains tick/day/week/year/season/time-of-day, width/height, ordered tile views (terrain, resource/crop/plant state), ordered entity views (id, kind, x, y), landmark views, night/weather flags and resolved sprite IDs. No pygame objects, mutable world references or RNG objects cross this boundary. A owns frame_from_world(state, config) -> WorldFrame; agree field definitions/sprite keys with B before edits depend on them.
4. B exposes Viewer(assets_config, display_config), pump() -> bool (false on quit), draw(frame: WorldFrame) -> None, save_png(path: Path) -> None and close() -> None. Camera input is local display state. Viewer never calls step, draws random numbers, writes SQLite or updates world objects. A's session controller invokes pump/draw and independently advances due ticks; headless uses the identical step unpaced. Live controller timing uses a monotonic clock and configured 0.36 seconds/tick divided by speed; rendering targets configured 30 FPS. Render FPS never enters simulation state or event payloads.
5. RNG streams use a stable hashlib digest of an unambiguous versioned seed/name encoding, independent random.Random instances, fixed subsystem/entity iteration and deterministic IDs. Save getstate(), including Gaussian cache, with validated JSON tuple/list conversion, plus original seed and all initialized stream names. Save pending schedule entries/counters, next IDs, habitat indices or reproducible reconstruction data, extinct-area deadlines and current resource/plant/crop timers. No seed-only restoration, salted hash, UUIDs or wall-clock fields in island events.
6. Config models share strict validation and extra='forbid' recursively. Reject wrong primitive types including bool-as-int, unknown nested keys, invalid odds, nonfinite values, nonpositive intervals/costs and invalid sheet coordinates with filename/full key in the error. All tunable counts/geometry/odds/cadences/capacities/timing/display values belong in TOML, not code. Constants defining formats (16px sheet cells, four rotations, serialization/schema versions) are distinct from tuning. Empty future package __init__.py files contain only a job docstring. balance.toml has validated sections, not fake working rules; models.toml has only schema-valid empty role structure and nomic-embed-text until Phase 4. No application SDK or dotenv key loading in Phase 1.
7. Map: rotate one entire home template including initial resources, plant/crop states and resident placement; IDs can differ, normalized contents cannot. Keep coast/centre decoration outside home extents. Configure home/centre/buffer/forest and ecology area IDs; centre has strictly more initial tree/farm/stone units than each home. Guarantee traversable corridors and walkable landmark access cells (lake dock on shore). A* uses four neighbours in a fixed order, cost of entering a destination tile, and admissible Manhattan distance times minimum positive traversal cost. Test unreachable goals and unequal costs, not only path existence.
8. Ecology: update the minute clock always; due systems run in stable (due_tick, subsystem_order, entity_id, serial) order. Schedule weather at equal-duration configured intervals that divide season length, with a new seasonal draw at every exact season boundary; odds are categorical clear/rain/storm/drought. Both rain and storm extinguish campfires; storm stops outdoor work; drought reduces seasonal spring/lake yields. Configure tree regrowth and over-cut thresholds per area, finite stone, actual farmland state transitions and no winter growth. Crop maturation occurs inside 20,160 ticks in the spring fixture. Plant seasons/cooldowns are explicit for all seven species. Animals have real movement, dog fleeing, habitat/carrying capacities and seasonal births; zero-population area cooldown blocks both births and immigration. Spring-only egg nests are cleared on season change. Initial dogs are 2-4 per pack only in buffer/centre forests; configured movement activity rises at night/winter and breeding is slower than rabbits under controlled conditions. No attacks in this phase.

Storage schema v1 (A freezes these names/types/relations before implementation; no ID-only future tables):
- Common rules: id INTEGER PRIMARY KEY and tick INTEGER NOT NULL CHECK(tick >= 0) where applicable; JSON columns are TEXT with json_valid checks, nonnegative token/cost checks, foreign_keys enabled per connection. Optional nested data is nullable, not fabricated. Use stable player IDs/human names separately from provider metadata. One DB scopes one run, so no run-name field in deterministic events.
- events: id, tick, type TEXT NOT NULL, payload_json TEXT NOT NULL; BEFORE UPDATE and BEFORE DELETE abort triggers. Prevent replacement of an existing event ID as well (BEFORE INSERT duplicate-ID abort guard), so INSERT OR REPLACE cannot erase history. Public API only appends/reads ordered events. No per-event wall-clock timestamp.
- ai_calls: id, tick, player_id TEXT NULL, role TEXT NOT NULL, provider TEXT NOT NULL, model_version TEXT NOT NULL, prompt_json TEXT NOT NULL, reply_json TEXT NULL, thinking_tokens INTEGER NULL, input_tokens INTEGER NOT NULL, output_tokens INTEGER NOT NULL, cache_read_tokens INTEGER NOT NULL, cache_write_tokens INTEGER NOT NULL, cache_hit INTEGER NOT NULL (0/1), cost_usd REAL NOT NULL, duration_ms REAL NOT NULL, status TEXT NOT NULL, error_json TEXT NULL, details_json TEXT NULL. No rows/calls now; measured real durations later live here, not in events.
- choice_points: id, tick, player_id TEXT NOT NULL, situation TEXT NOT NULL, x REAL NOT NULL, feeling TEXT NOT NULL, tier TEXT NOT NULL, thought TEXT NOT NULL, noticer_read TEXT NULL, advisor_said TEXT NULL, advisor_followed INTEGER NULL (0/1), action_json TEXT NOT NULL, self_label_json TEXT NOT NULL, outcome_json TEXT NULL, insight TEXT NULL, ai_call_id INTEGER NULL REFERENCES ai_calls(id), details_json TEXT NULL. Judge labels link through their separate table; hooked helper fields remain NULL.
- judge_labels: id, tick, choice_point_id INTEGER NOT NULL REFERENCES choice_points(id), ai_call_id INTEGER NULL REFERENCES ai_calls(id), detail_level TEXT NOT NULL, label_json TEXT NOT NULL, details_json TEXT NULL.
- chats: id, tick, speaker_id TEXT NOT NULL, target_ids_json TEXT NOT NULL, hearer_ids_json TEXT NOT NULL, text TEXT NOT NULL, details_json TEXT NULL.
- value_history: id, tick, player_id TEXT NOT NULL, game_week INTEGER NOT NULL, value_id TEXT NOT NULL, old_weight REAL NULL, new_weight REAL NOT NULL, cause_event_ids_json TEXT NOT NULL, reflection_ai_call_id INTEGER NULL REFERENCES ai_calls(id), details_json TEXT NULL.
- spend: id, tick, ai_call_id INTEGER NULL REFERENCES ai_calls(id), role TEXT NOT NULL, cost_usd REAL NOT NULL, cumulative_usd REAL NOT NULL, details_json TEXT NULL. Snapshot spend is 0 in Phase 1.
- snapshots: id, tick, last_event_id INTEGER NULL REFERENCES events(id), schema_version INTEGER NOT NULL, config_json TEXT NOT NULL, config_hash TEXT NOT NULL, state_json TEXT NOT NULL, rng_json TEXT NOT NULL, spend_usd REAL NOT NULL. State includes seed, schema/runtime compatibility identity, due schedules and next IDs. JSON config pins the simulation's effective parameters; reopening never silently adopts edited tuning.
- Commit event appends in bounded configurable batches, not one fsync per tile/entity/tick. Snapshot creation flushes pending events and writes the snapshot in the same transaction at a complete tick. Autosave every configured 360 ticks plus every clean shutdown/finite command exit; snapshot at initialization. Restore highest snapshot with matching watermark/config, validate unsupported versions before stepping. An unexpected committed event tail is an explicit unsupported-crash-recovery error in Phase 1; never truncate/rewrite events or append duplicates. Full tail replay/UI recovery belongs to Phase 3, and paid-reply reuse to Phase 4.

CLI semantics (proposed defaults to remove ambiguity):
- new <run> [--seed N]: validate run is a single safe path component; refuse existing run.db; create all tables, seeded world and tick-0 snapshot, then return.
- headless --ticks N without --run: fresh ephemeral session using explicit seed or run.toml default; run exactly N ticks, print final game time, no live pacing. Tests needing persistent event comparison use distinct named runs.
- headless --ticks N --run <run>: create a missing run from configured/explicit seed, otherwise restore existing run and append N ticks; reject explicit seed conflicting with saved seed. Clean exit saves latest completed tick.
- resume <run>: require existing DB; restore latest snapshot and continue persistent live controller/viewer until quit, save on exit. Does not refuse an existing run and does not generate another world.
- view [--run <run>]: with an existing named run, live controller restores/advances/persists it; without a run, fresh ephemeral live island from configured seed. Observer remains read-only in both cases.
- view --ticks N --screenshot <png>: run exactly N steps unpaced on a fresh world or isolated loaded copy of --run, draw once, save PNG and exit. With --run, source DB is read-only and unmodified; never advance it or append events. Controller creates PNG parent directory. Load/audit every manifest sprite even if not visible in that frame. Works with SDL_VIDEODRIVER=dummy.

Asset contract: assets.toml has named pack/code entries for every Gameplay item and required state/variant, plus a missing section for every code fallback. Enumerate four players, bounded villager variant set (50 is population cap, not 50 unique required art files), every tool/basic/better variant, all structures/damaged variants, crops/plants/terrain states and all UI concepts. UI layout/font entries are explicitly concept icons with real 16x16 code renderers in Phase 1; they do not claim to load monogram or build widgets. Actual monogram font and full tabs/controls remain Phase 3 per phases.md:119. No missing image is silently substituted. Kenney crop origin is (column*17,row*17), bounds 49 columns/22 rows, crop 16x16. Recolour foreground black and normalize alpha to binary; white background, unfiltered integer scaling and binary dithering/masks for overlays. Set Windows DPI awareness before window creation; initialize display before convert_alpha or avoid display-dependent conversion. 1280x1280 base island can scroll at scale 1; do not fractionally shrink it. Do not read Urizen. Asset files remain unchanged.
