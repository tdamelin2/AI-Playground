## Ideas (best first, at most 5)
### Idea 1: Durable complete-tick journal with verified deterministic replay
What: Treat a fully resolved tick as the durability boundary. Add a typed `tick_committed` event at the end of every minute in every Simulation execution mode, including ecology-only and in-memory runs; persist that tick's events, chat projections and marker atomically. Autosave remains a full JSON state every 360 ticks. Restore the latest snapshot and deterministically re-execute each complete journalled tick, compare canonical generated events to stored events, and suppress all replay writes. | Covers: AC-9, AC-10, AC-11, AC-16; Phase 4 replay extension.
Why better: Existing events describe outcomes, not enough state transitions to apply as an event-sourced world. Re-executing the exact seeded simulator restores RNG, scheduler and controller state; comparison detects code/config drift rather than silently changing history. The marker locates eventless minutes and rules out a partial tick tail. Example: snapshot tick 360; committed markers through 417; crash inside tick 418 -> restore/replay to 417, continue at 418 without duplicate events/chats. A physically unfinished tick cannot be recovered as finished. | Trade-off: One durable transaction per attached tick costs disk time; benchmark against the existing year fixture, keep headless in-memory tests free of disk commits. Never change synchronous/journal settings to unsafe values for speed. Avoid appending pause/autosave UI events to the scientific event stream, because their wall-time-dependent insertion would break equality. | Effort: High.
Touches: sim.py, storage/db.py, storage/events.py, new storage/recovery.py and storage/session.py, cli.py. `Simulation.step` and `run` must share the same finalization path; `advance_to` cannot leap over persistence/autosave boundaries. Keep DB SCHEMA_VERSION=1. Snapshot format need only change if new simulation-owned accumulators require it; record this separately.
Fits Overview.md: yes; append-only eight-table database, JSON state, no AI/network, same seed and event log. Add a decision-source seam now: replay decision lookup keyed by `(tick, player_id, decision ordinal)`; Phase 4 can supply recorded replies. Do not implement real AI calls now. | Sources: [SQLite transactions survive crashes atomically](https://www.sqlite.org/transactional.html), [SQLite isolation](https://www.sqlite.org/isolation.html). Recommendation is an application design inference from these guarantees and existing seeded simulator.

### Idea 4: Auditable weekly measures from semantic effects and sampled welfare
What: Define an explicit event-backed no-AI measurement vocabulary, then fold it into per-game-week reports with actor/partner breakdowns. Promises use `promise_made/kept/broken` IDs; harm uses one `harm` event per actual effect; belief uses `belief_act`; help gets a new semantic successful-effect event because ActionFinished has neither target nor reliable success semantics. Average loyalty uses deterministic minute samples of alive villagers attributed to the leader at sampling time, with persisted numerator/count and completed-week result events. | Covers: AC-13, AC-14; preserves AC-11 and AC-16.
Why better: Counting issued actions credits failures; counting XGain as help double-counts bonuses; calculating average loyalty from the final world erases deaths/departures and transfers. Explicit fields prevent these quiet analysis errors. Example: samples (leader P1, loyalty 60), (P1,80), then transfer to P2 and sample 50 -> P1 mean70, P2 mean50. A leader with no villager-minute samples yields null, never zero. | Trade-off: Requires a few narrow hooks at successful social/work effects; tester needs scripted success and failure examples. Loyalty sampling needs snapshot state or compact persisted sample events; prefer accumulators persisted with Simulation state and a `weekly_measure` typed event, avoiding a ninth table/migration. | Effort: High.
Touches: new measure/weekly.py, storage/events.py, sim.py snapshot/restore hook, rules/turn.py or completion hooks, selected actions social/build/core (manager must inspect before assigning exact hooks).
Fits Overview.md: yes. Derive weeks from pinned clock's ticks_per_day * days_per_week, not report.py's hard-coded seven/1440. ### Idea 5: Bounded session work, scoped Windows awake request and consistent exports
What: Let session own pause/request/resume/close, wall-time tick debt, autosave status and Windows awake state. Cap catch-up work per UI iteration; preserve tick debt during ordinary slow frames, discard paused elapsed time on resume. Export all eight tables through one read transaction, streaming UTF-8 CSV with headers even when empty. | Covers: AC-2, AC-7, AC-9 through AC-12, AC-14, AC-15.
Why better: Current `_cmd_view` can run 5000 ticks before pumping the window again. Bounded work protects P/button response and 30fps while zero-tick frames still render. The awake request is set only for active sessions, cleared on pause and in finally on every exit/error. Read-transaction export sees one coherent database state rather than different table times. | Trade-off: A small injectable monotonic clock and keep-awake adapter make state transitions testable; mock Windows calls in tests rather than depending on the test host's real sleep timer. Exporting snapshot JSON creates large CSV cells, so stream rows. | Effort: Medium.
Touches: storage/session.py, storage/power.py, measure/export.py, cli.py, config.py/run.toml; ObserverScreen consumes status and control intents only.
Fits Overview.md: yes; standard-library csv/sqlite3/ctypes/pathlib. SetThreadExecutionState with ES_CONTINUOUS|ES_SYSTEM_REQUIRED (`0x80000001`); release with ES_CONTINUOUS (`0x80000000`) on the same thread. No away-mode or forced display-on needed. CLI `export --run NAME` -> runs/NAME/exports/{events,ai_calls,choice_points,judge_labels,chats,value_history,spend,snapshots}.csv. Preserve schema column order, JSON as JSON strings, SQL NULL as empty field, stable primary-key row order; newline='' for CSV writer, proper quotes/newlines/non-ASCII. If reporting weekly results separately, weekly.csv is additional and must not replace any table export. | Sources: [Microsoft SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/desktop/api/winbase/nf-winbase-setthreadexecutionstate), [SQLite isolation](https://www.sqlite.org/isolation.html).
