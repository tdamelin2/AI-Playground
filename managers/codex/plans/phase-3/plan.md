### Session and durability contract
- New `storage/session.py:RunSession` owns a Simulation, the writer connection, monotonic timing and power adapter. `request_pause()`, `resume()`, `set_speed(value)`, `close()` are the only control operations handed to the observer. `advance(now: float, budget_seconds: float)` runs complete ticks outside observer code. Read-only `status()` returns frozen `SessionStatus(paused, speed, tick, saved_tick, saved_reason, spend_usd, cap_usd, warning, error)`; saved_reason is `initial|autosave|pause|exit`. A failed commit/save yields paused+error, never a success indicator.
- One shared Simulation minute-finalization path is used by step(), paced run(), unpaced run(), live session and recovery. Execute all scheduler jobs through minute T with `advance_to`, sample welfare, then append `Event(tick=T, payload=TickCommitted())` as the final event of T; TickCommitted.type is 'tick_committed'. Marker appears at every minute even without people/gameplay events and without a DB. No marker at T=0. Marker payload need not repeat the Event.tick. Do not emit pause/frame/speed/autosave wall-time events into the deterministic journal.
- `RunDB.append_complete_ticks(events)` writes only whole-tick groups, their chat rows and final markers in one transaction. Group boundaries may differ by mode; journal rows may not. Headless batching can honor run.event_batch, but never split a tick. Live session commits before publishing a new frame/status tick. Snapshots at 0 and each autosave boundary are complete and atomic with their pending events. This avoids mandatory 80,640 separate disk syncs per game year.
- `storage/recovery.py:recover(db, assets=None) -> Simulation` loads the latest supported snapshot and re-executes through the last committed marker after its last_event_id. Compare each generated `(tick,type,canonical payload)` against stored rows, including marker order. Never append already stored events or regenerate chats-table rows. Compare the entire tail before enabling normal writes. Any missing/interior marker, event after the final marker, drift or malformed state stops with a diagnostic and leaves the DB unchanged. A snapshot itself is a trusted boundary even when an older clean Phase 2 snapshot has no markers before it.
- Recovery example: snapshot 360, tail committed through 417, process killed during 418 before commit -> recovered tick417; running another 583 ticks produces exactly the uninterrupted journal through tick1000, with each chat once. A kill during a grouped transaction either preserves the whole group or rolls it back. Recovery promises the last durable completed tick, not partially resolved/uncommitted RAM work; the screen never acknowledges the latter.
- Replay decision seam: `DecisionSource.decide(ctx: DecisionContext, ordinal: int) -> ActionRequest|None`; ordinal starts at0 for each `(tick, player_id)`. Ordinary dummy/scripted controllers still advance and restore their own state. Phase4 may provide a recorded-reply source keyed by `(tick,player_id,ordinal)`; no provider SDK/reply retrieval is implemented in Phase3, and a missing replay decision must never fall back to a paid call.
- `run.autosave_interval=360` remains game ticks: advance 0->721 yields autosave ticks360,720, regardless of batching/pacing. Pause at417 saves417, next periodic autosave is720, not777. Pausing at a tick boundary stops before the next minute; a request during a tick applies after its finalization/commit. Pause saves once per transition. Close saves at the current completed tick. `resume()` resets the wall-time origin so sleeping/paused elapsed time creates no catch-up ticks. Ordinary slow-frame debt is retained. `view.fps=30`, new validated `view.max_tick_work_ms=10.0`; budget exhaustion returns to the UI between ticks. One unusually slow tick can exceed the budget; report measured pacing honestly.
- New validated run.toml keys `max_dollars=100.0`, `spend_warning_ratio=0.8`; positive cap and ratio in(0,1]. Add compatible defaults for keys absent from pinned Phase2 configs, without altering the raw config string before verifying its stored hash. Persist true spend in Snapshot.spend_usd instead of the current constant0. Authoritative total is SUM(spend.cost_usd), never SUM(cumulative_usd); recovery does not add snapshot spend to the entire ledger again. Ledger rows inserted for tests are preserved. At costs0.1,0.2 -> total0.3; warning at80/100, no warning at79.99/100; empty table displays$0.00. Phase4 still owns pre-call budget enforcement.
- `storage/power.py:AwakeGuard.set_active(bool)` requests `SetThreadExecutionState(0x80000001)` while running and `0x80000000` on pause/exit, on the same owning thread, with finally cleanup. No-op off Windows. Return0 means a failed OS request, exposed in status; it must not claim the laptop is protected. Tests inject a fake adapter; agents never change actual machine sleep settings during planning.

### Measures, commands and acceptance examples
- `measure/weekly.py:game_week(tick,clock)` uses max(0,tick-1)//(ticks_per_day*days_per_week)+1: ticks1 and10080->1,10081->2,80641->9 with default config. Closing events at a boundary belong to the week just completed; display clock at10080 may already show week2. Aggregate weeks never reset with the season/year.
- Add typed `HelpEffect(actor,recipient,action_id,kind,unit)` at actual successful effects for gift (items/tools), use_herb on another actor with an actual body improvement, teach to the addressed other player after knowledge insertion, build/build_shrine positive work on another player's structure, repair that raises HP on another player's structure. Exclude self-care, failed actions, reciprocal trade, overhearers, and guard without an observed effect. These are operational action categories, not moral/judge labels; teaching false information still counts as a teaching action and later judge analysis may disagree. Capture the recipient at effect time. Add optional action_id to Harm from the actor's active action; no change to harm outcomes.
- Help/harm action counts deduplicate globally by(actor,action_id,recipient), assign to the first successful effect's week, and retain kind/recipient breakdowns. Legacy harm with no action_id falls back to its unique harm.id and declares historical granularity. Example one interrupted gift action transfers twice to P2 ->one help action, two effect rows; failed gift ->zero; subsequent new gift action ->one more. A cancelled action's completed positive effects remain counted. Existing Harm supplies steal/sabotage/attack/chase_off/pull_stakes/capture/poach evidence, without double-counting ActionFinished/XGain.
- Each finalized minute with people emits one compact `WelfareSample(leaders: dict[str,LoyaltySample], unled:LoyaltySample)`, LoyaltySample={loyalty_sum:float,count:int}, from alive villagers at end-of-tick, sorted leader keys. No accumulators enter the snapshot; fold sample sums/counts for the requested week. Per leader and island-wide means are minute-weighted; unled includes living wanderers/captives with no leader. Example P1 samples60,80; P2 sample50 ->means70,50; island190/3. No living sample ->null with sample_count0. Historical weeks without samples show unavailable/coverage, not a false zero.
- `weekly_measures(db, through_tick) -> tuple[WeeklyRow,...]`; WeeklyRow contains absolute_week,player_id,partner_id,metric,kind,count,value,sample_count,coverage_ticks,complete. Metrics: promises_made/kept/broken, help_actions, harm_actions, villager_deaths, villager_departures, average_loyalty, belief_actions. Promise made week1 then kept week2 ->made1 inweek1, kept1 inweek2 for maker/partner; do not divide unrelated weekly cohorts into a fulfillment rate. Death/departure attribution uses leader in the event. Belief counts only belief_act including pray,ceremony,offering,build_shrine; do not count ActionFinished again or infer superstition. Emit zero count rows for present player/week cohorts, explicit null means, and partial-week complete=false. No ninth SQL table is required. `main.py measures --run NAME` prints all completed/partial weeks; export adds weekly.csv alongside the eight tables.
- CLI: `uv run python main.py new p3_watch --seed 1 --players dummy` creates a fresh run; `uv run python main.py watch --run p3_watch` opens persisted full observer and recovers if necessary. Existing `resume p3_watch --ticks 1440` stays bounded/headless. Watch requires an existing run and one active writer per run (lock/busy error must be clear). No new command creates or selects AI seats.
- `view --run p3_watch --ticks 60 --screenshot logs/p3_observer.png` keeps the existing flags/validation and includes top bar and tabs. Clone the source database into memory, recover/preview there, append preview events/chats only there, and use its query provider. Source rows/snapshots/spend unchanged. No-run screenshot uses an in-memory full-schema database. Read-only non-screenshot view remains preview-only; its pause controls stop preview, not a source run. Preview status must say it is a preview.
- `measure/export.py:export_run(db_path,output_dir=None)->dict[str,int]`; `uv run python main.py export --run p3_watch` defaults to runs/p3_watch/exports/. One coherent read transaction streams each of events,ai_calls,choice_points,judge_labels,chats,value_history,spend,snapshots to TABLE.csv in schema column order and primary-key order. UTF-8, newline='', csv.writer, SQL NULL empty cell, JSON preserved verbatim. Empty ai_calls exports its header and0 rows; chat containing comma,newline,Hebrew and quotes reimports as one row with original text. Row-count mapping e.g. chats:3 means exactly3 parsed records beyond header. No source DB mutation. weekly.csv is additional, never a substitute for any table. Use a separate consistent export read view so the GUI does not hold an open writer transaction.
