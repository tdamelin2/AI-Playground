## Ideas (best first, at most 5)

### Idea 1: One resumable action contract, one simultaneous commit
What: Make a strict ActionRequest and a persisted RunningAction the common path for dummy players, scripts and later AI replies. Progress produces candidate effects; resolve conflicting candidates together before mutating shared stocks. | Covers: AC-11..14, AC-18, AC-21, AC-30..32; human movement requirement.
Why better: Prevents a separate special-case implementation per test player, lost partial work, double harvesting and headless/view timing differences. Existing resource APIs mutate immediately, so the arbitration boundary must precede calls to them. | Trade-off: Requires a central coordinator and explicit discrete versus continuous work semantics. | Effort: High.
Touches: src/ai_island/rules/actions.py, src/ai_island/rules/resolution.py, src/ai_island/sim.py, src/ai_island/world/engine.py, src/ai_island/world/movement.py, src/ai_island/world/state.py, src/ai_island/minds/.
Contract: ActionRequest has kind, actor_id, typed target/parameters and exactly one of amount or until_tick where applicable; a rest-until-morning endpoint is converted to an absolute game tick. RunningAction has action_id, request, start_tick, last_progress_tick, progress, committed_units, reserved inputs, path/path_index and status. Preserve fractional work and completed units on interruption; unfinished construction remains a project keyed by id. Define cancellation/refund policy for unconsumed inputs. Start at T, never finish a positive-duration action before T+1. Phase pipeline: ecology/arrivals and body updates; observations and interrupt edges; collect decisions; progress/resolve a stable candidate batch; chat; log/summary. All due actors read the same decision-time projection. Conflict keys identify the actual scarce resource, not merely action kind; draw a winner from a sorted contender list using the resolution stream, then rotate normal player precedence by tick. Revalidate available stock at commit. Add single-animal-id removal for hunting/fishing: remove_animals currently removes an entire zone and must retain that earlier API behavior. A recurring phase2 coordinator scheduler job can preserve existing advance_to daily chunks; do not bypass minute updates. For humans reuse begin_step/complete_step/step_minutes via a structural mover contract and A*; calculate ceil(walk_minutes * entered_tile_cost / feeling_speed). Keep human path execution separate from animal register/spec_for/start caps, preserving the existing animal/dog wander heap and its RNG draws. Logical tiles change only on arrival; pending interrupt stops at the last arrived tile or after the current step, with one documented policy and tests.
Fits Overview.md: yes; pure Python rules, existing primitives, no new dependencies or AI. | Sources: none (local source/spec).

### Idea 2: Conserved item and project ledgers rather than loose counters
What: Give every item batch/tool, structure, fire, land claim, promise, task and contribution a stable identity and one authoritative persisted record. All transfer actions use the same ownership/location operations. | Covers: AC-6, AC-14..19, AC-22..23, AC-30..31.
Why better: A tool can be crafted, repaired, stolen, traded, dropped and lost on death without six inconsistent implementations. Shared project contributions and landmark occupancy become auditable instead of inferred from final ownership. | Trade-off: More small data records and round-trip tests. | Effort: High.
Touches: src/ai_island/world/state.py, src/ai_island/rules/inventory.py, src/ai_island/rules/tools.py, src/ai_island/rules/buildings.py, src/ai_island/rules/social.py, src/ai_island/rules/tasks.py, src/ai_island/rules/land.py, src/ai_island/storage/events.py, src/ai_island/sim.py.
Contract: ItemStack has id, kind, amount, holder/container or ground position, acquired_tick and spoil_due; tools also tier/durability. Split batches without resetting spoilage. A single move_items validates and transfers; conservation covers both barter legs and consumes nothing without both acceptances and successful final revalidation. TradeOffer identifies participants, exact stacks/quantities, acceptance set and expiry; acceptance cannot duplicate transfer. Promise has promisor, beneficiaries, machine-checkable predicate, deadline and one terminal result. No text-parsing oracle; free-form promise text may be recorded separately. Structures hold type, owner, hp, location and completed/project state; fires hold kind and fuel_until; bounded integer recipes define half-price repair rounding. Land ownership is separate from ecological zone_grid; stakes map to claim tiles and removing a stake updates ownership/borders. Landmarks persist exclusive eligible occupancy minutes per player and interval boundaries. Tasks are five config-defined stage predicates with once-only reward flags; recruitment rewards transfer an existing wanderer, never create a villager. Joint projects persist actual contributed work/resources per player and once-only rewards. Snapshot all new state including offers, pending chat, interrupts, scripted cursor, action fractions and report accumulators; increment snapshot layout if old saves are rejected, leaving SQL SCHEMA_VERSION=1.
Fits Overview.md: yes; JSON state and existing eight SQL tables suffice. | Sources: none (local source/spec).

### Idea 3: Observations are evidence projections, never raw world events
What: Separate omniscient logged effects from recipient-specific observations. Record witnesses when an effect happens, then create short human-only sense text and knowledge entries from that evidence. | Covers: AC-10, AC-13, AC-17, AC-24..28, AC-31.
Why better: The victim can notice missing goods without learning a hidden thief's identity, and villagers cannot gossip about unseen events. The same evidence powers future AI memory without exposing private stores, tasks, X or poison labels. | Trade-off: Requires deliberate event visibility metadata and negative privacy tests. | Effort: High.
Touches: src/ai_island/rules/discoverer.py, src/ai_island/rules/chat.py, src/ai_island/rules/interrupts.py, src/ai_island/minds/knowledge.py, src/ai_island/world/state.py, src/ai_island/storage/events.py, src/ai_island/storage/db.py.
Contract: PerceivedEvent has source_event_ref (persisted simulation-local event sequence; SQL ids do not exist before flush), observed_tick, observer_id, modality, visible actor identity or unknown, public facts and provenance. Sight/hearing computed from logical positions at the event's phase, not next-tick position; consistent configured Manhattan radius is the simplest fit to existing movement. Direct talk requires target in sight; delivered words go to every hearer within hearing radius and no others, next sense cycle. A visible target beyond hearing range exposes a spec edge that needs a settled delivery policy. Witness gossip is player-related evidence only; reported information keeps speaker/provenance and may be false. KnowledgeEntry has id, claim, confidence in [0,1], source and learned_tick; teaching copies the stated claim with lower confidence, never upgrades it using hidden world truth. RememberedTile holds last_seen_tick and the old visible tile state, updated only in sight. Interrupts are edge events: visible entity set difference, weather transition, band transition, noticed loss; avoid every-minute duplicate interrupts. Deduplicate/coalesce queue entries without discarding distinct causes. Each sense event kind gets at least three templates; choose via a dedicated senses stream (or stable event/recipient selection), so viewing/reporting cannot change the run RNG. Do not expose numeric X or internal species toxicity names to decision policies.
Fits Overview.md: yes; deterministic code Discoverer, human-facing names, no model. | Sources: none (local source/spec).

### Idea 4: Shared body integration with separate wellbeing and social state
What: Use the same elapsed-minute body integrator for players and villagers; keep loyalty, bonds, trust/anger and wellbeing adaptation as separate fields with distinct update rules. | Covers: AC-1..9, AC-15, AC-20, AC-31.
Why better: Poison, hunger, cold and hard work have consistent consequences; bond cannot accidentally act as loyalty or instant recruitment permission. Delta-time formulas make batching and resume predictable. | Trade-off: Requires carefully specified units, clamping boundaries and death order. | Effort: High.
Touches: src/ai_island/rules/needs.py, src/ai_island/rules/wellbeing.py, src/ai_island/world/villagers.py, src/ai_island/world/dogs.py, src/ai_island/rules/combat.py, src/ai_island/config.py, config/balance.toml.
Contract: Needs normalized to [0,1], health/pain with stated scales, sickness kind/severity/deadline and last_update_tick. Positive wellbeing inputs use concave saturating f(c)=1-exp(-k*c), with nonnegative weights and configured k, then X=clamp(sum(w*f)+B,0,100). Convert bad needs to positive adequacy inputs; do not apply concave curves directly to deficits with ambiguous signs. B decays once per elapsed interval with half_life=2880 minutes, then applies new gains/losses exactly once. Feeling bands use real interval boundaries [0,20), [20,40), [40,60), [60,80), [80,100]; propose speed/work factors 0.15/0.4/0.7/1/1, tunable and commented because the design specifies words but no exact slower factors. Hooked is X<40 OR pain>=threshold. Death drops inventory once, cancels motion/action once and respawns players; test the effective immediate X decrement after body reset so a reset does not erase the stated -10 penalty. Villager finite registry: 12 initial followers plus a configured precreated wanderer pool, total<=50, dead ids never reused and no births. Loyalty starts 70 and leaving requires <30; derive daily deficits so the earliest hunger/overwork departure is after a chosen several-day exposure, recorded in metrics. Bonds are a per-villager map over all four players, independent from current leader loyalty. Dog targeting considers fire, spear and local group size before selecting lone/unarmed targets; claimed boundaries must not accidentally provide immunity if home attack behavior is required.
Fits Overview.md: yes; all coefficients in strict TOML models, no pygame/AI in world/rules. | Sources: none (local source/spec and elementary formulas).

## Questions
- AC19 says all belief actions change nothing else, but a shrine is also a buildable structure and an offering ordinarily consumes an item. Suggested resolution: belief pray/ceremony/shrine/offering log only (no inventory, X, RNG, weather changes); mechanical build(kind=shrine) is the ordinary structure action with costs. Manager should settle naming/coverage explicitly rather than silently picking one interpretation.
- Landmark holding says sole presence for most of a week and dominance after a full week. Suggested fixed weekly interval with one owner's exclusive eligible occupancy > half the interval, reward once at interval end; decide fixed versus rolling week and whether contested minutes invalidate or simply do not count.
- What exact shortage definition, no-store dummy profile and adverse exposure duration does AC29 mean? Suggested baseline seed1, 3 full days minimum adverse exposure, first failed home-food acquisition plus companion stock series; require nonempty winter cohort and report per home/player. These are proposed measurement contracts, not facts already specified.
- Is a direct listener in sight but outside hearing allowed to receive speech? AC27 requires everyone within hearing and nobody else; suggested require both visibility and hearing for audible targeted talk, with a clear rejected-action reason.
- Does high pain respawn restore needs immediately, and how is -10 X measured? Suggested define same-tick net displayed X drop after reset with clipping at zero and a decaying B adjustment; otherwise resetting hunger can increase X despite the penalty.
- Exact task predicates/unlocks, starting inventory/pool size and qualitative speed/work factors are unspecified numeric design choices. Put proposed values with reason comments in the merged contract before implementation; do not present them as sourced fixed requirements.
