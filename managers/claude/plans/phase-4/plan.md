C1 llm/types.py (A)
- `Usage(input_tokens:int, output_tokens:int, thinking_tokens:int|None, cache_read_tokens:int, cache_write_tokens:int)`
- `PromptLayers(fixed:str, slow:str, call:str)`; `LLMRequest(role_key:str, player_id:str|None, purpose:str, layers:PromptLayers, schema:type[BaseModel], max_output_tokens:int, call_key:str, meta:dict)`. `purpose` in {fast, noticer, advisor, main, ranking, reflection, judge}. `role_key` is a models.toml role id (C3). `meta["fallback"]` = an ActionRequest dict the fake adapter's auto mode may use.
- `LLMResult(status: Literal["ok","format_error","refusal","network","rate_limit","sleep","cap"], parsed: BaseModel|None, raw_text:str, usage:Usage, model_version:str, cost_usd:float, duration_ms:float, attempts:int, ai_call_ids:list[int], reused:bool)`
- `Adapter` protocol: `complete(request: LLMRequest, role: RoleConfig) -> RawReply` where `RawReply(text:str, usage:Usage, model_version:str, refused:bool)`; raises `NetworkError`, `RateLimitError` (llm/errors.py). Pydantic validation happens in the gateway, not the adapter.
- Adapters: `AnthropicAdapter(client)`, `OpenAIAdapter(client)` (also xAI with `base_url="https://api.x.ai/v1"`), `GoogleAdapter(client)`, `MistralAdapter(client)`, `FakeAdapter(script=None, delays=None, failures=None, bill=False)`; `OllamaEmbedder(client, model)`, `FakeEmbedder(dims=64)` (bag of hashed lowercase words, sha256 per word, L2-normalised; same text -> same vector). Real clients are built only by `llm/factory.py make_adapter(provider)` which loads `.env` with python-dotenv at call time; tests always inject mock clients.
- Anthropic: system = list of two text blocks (fixed, slow) each with `cache_control={"type":"ephemeral"}`; user message = call layer; structured output through the SDK's JSON-schema output mode for the model chosen (fallback: a single forced tool whose input_schema is the Pydantic schema). OpenAI/xAI: `response_format` json_schema strict, messages [system fixed+slow, user call]. Google: `response_mime_type="application/json"`, `response_schema`. Mistral: `response_format` json_schema. Each maps usage fields to `Usage` (thinking: Anthropic none-unless-reported, OpenAI `reasoning_tokens`, Google `thoughts_token_count`).
- Refusal mapping: Anthropic `stop_reason=="refusal"`, OpenAI/xAI `message.refusal` non-empty, Google `finish_reason` SAFETY/PROHIBITED_CONTENT, Mistral finish_reason "content_filter"; plus the gateway marks status refusal when the parsed reply's free text matches `[llm] break_character_phrases` (case-insensitive).

C2 llm/gateway.py (A)
- `CallBroker(db: RunDB|None, models: ModelsConfig, llm_cfg: LlmConfig, adapters: dict[str, Adapter], spend: SpendLedger, sleep=time.sleep, wall=time.time, replay=False, wait_hook=None)`.
- `broker.run(pipelines: dict[str, Generator[LLMRequest, LLMResult, T]]) -> dict[str, T]`: starts every pipeline, submits each yielded request to a ThreadPoolExecutor (max_workers = `[llm] max_parallel` = 8), sends each LLMResult back into its generator, returns when all generators have returned. Calls from different players overlap; one player's calls are sequential. While waiting it calls `wait_hook()` every `[llm] wait_hook_seconds` (0.05). All DB writes happen on the calling thread.
- Before sending: (1) reuse: `db.find_call(call_key, attempt)` returning an ok/format_error/refusal row -> rebuilt result with `reused=True`, no spend; (2) `replay=True` and no stored row -> `ReplayMissingError`; (3) cap: if `spend.total + estimate(request, role) > spend.cap` -> status "cap", no call, raises `RunPaused("spend_cap")` after the batch's other pipelines finish their in-flight call.
- Retry: format error (JSON or Pydantic fails) -> one retry (attempt 2) then status format_error; refusal -> no retry; NetworkError/RateLimitError -> waits `[llm] retry_waits_s = [2, 8, 30]` (3 retries, 4 attempts) then `RunPaused("network")`; a call whose wall-clock duration exceeds `[llm] sleep_gap_s` (300) and failed with NetworkError -> `RunPaused("sleep")` at once, no retries. Every attempt writes one ai_calls row (status ok|format_error|refusal|network|rate_limit|sleep).
- call_key = `f"{tick}:{player_id}:{seq}:{purpose}"`, seq = the n-th request this player made in this tick (0-based). Stored in `ai_calls.details_json {"call_key","attempt","purpose"}`.
- Estimate: `ceil(len(fixed+slow+call)/[llm] chars_per_token(4)) * input price + (max_output_tokens + thinking_budget) * output price`, prices per million tokens. Example: 4000 chars, max_output 500, thinking 0, input $3/M, output $15/M -> 1000*3e-6 + 500*15e-6 = $0.0105.
- Cost: `cost_usd(role, usage) = (input - cache_read - cache_write)*in + cache_read*cached_in + cache_write*cache_write_price + (output + thinking)*out`, all /1e6. Example: role in 3.00, cached 0.30, cache_write 3.75, out 15.00; usage in 10000 (cache_read 8000, cache_write 0), out 300, thinking 200 -> 2000*3 + 8000*0.3 + 500*15 = 6000+2400+7500 = 15900 /1e6 = $0.0159.
- FakeAdapter: model_version "fake-1"; usage input=ceil(chars/4), output=ceil(len(reply)/4), thinking 0, cache_read = ceil(len(fixed+slow)/4) when the same player+purpose family sent the same fixed+slow before, else 0; cost $0 unless `bill=True` (then the role's prices). Auto mode replies a valid instance of `request.schema` built from `meta["fallback"]` (action) and fixed text; script mode pops replies from `script[(player_id, purpose)]` (lists of dicts or raw strings, so bad replies can be scripted); `failures[(player_id, purpose)]` = list of "network"/"rate_limit"/"refusal"/"sleep" consumed per attempt; `delays[(player_id, purpose)]` seconds. Deterministic.

Layer 1 (fixed) per player and family ("player" for fast/main/ranking/reflection, "noticer", "advisor"): the opening guide (gameplay.md text, names filled), the value library, the action list ("things you can do"), both reply formats; byte-identical for every call of that player+family in a run. Layer 3: sense report text, memories, the question. `check_clean(text)` raises `PromptLeakError` on any `[prompts] banned_words` whole-word match (case-insensitive), run on every layer before a request is yielded.
- Router (minds/router.py): `route(ctx, state) -> Literal["reflex","fast","slow","hooked"]`: reflex if any `report.needs[n] >= reflex_levels[n]` and the reflex code finds an action; main if any taken interrupt kind in `main_interrupts` or spoken_to from a player, or a fast reply returns `needs_more_thought=true` (escalation: one extra main call); main -> "hooked" if `ctx.hooked` else "slow"; else "fast". Example: ctx with needs hunger 3 -> reflex, 0 calls; spoken_to from p2, unhooked -> slow, calls noticer, advisor, main in that order; same hooked -> hooked, calls main only with `recent(stream, hooked_k)` and no retrieve; finished gather, no interrupt -> fast, 1 call (helper role).
- `AiController(pid, world, runtime, cheap)`: `pipeline(ctx)` generator (yields LLMRequests, returns ActionRequest|None), `decide(ctx)` (runs pipeline through the broker, for tests), `day0_pipeline()` (ranking at the first decision), `reflect_pipeline(week)`, `to_state()/from_state()` (weights, invented values, identity, relationships cache, stream text, summary, pending outcomes, mistakes). Role ids: main = `p{index}_main` (or `p{index}_helper` when cheap), helpers `p{index}_helper`.
- Choice points (minds/choice.py): written for every slow/hooked decision, and for fast decisions whose action kind is in harm kinds (steal, sabotage, attack, chase_off, pull_stakes, capture, poach), promise (or the promise is broken: `check_promises` broken event for the player), or self_label.direction == "against". Hooked rows: noticer_read and advisor_said NULL, advisor_followed NULL. advisor_followed = chosen kind == recommended_action_kind. Outcome filled when the action finishes or fails: `{"result":"finished"|"failed"|"interrupted","x_before","x_after","x_delta"}`. Mistake when `x_delta < expected_feel_or_chosen_feel_now * x_per_feel_point - margin_x` (example: expected_feel +3 -> expected +6; actual -5 < 6-10 = -4 -> mistake). Insight filled at the weekly reflection from `insights[0]`.
- Weekly reflection runs after the last tick of each game week (tick % week_ticks == 0) for every AI seat, through the broker; prompt includes the week's mistakes and choice points; writes one value_history row per value (old, new, cause_event_ids = the mistake/choice point event ids cited), and `values_changed`.

## Findings
- The DB tables (ai_calls, choice_points, value_history, spend, judge_labels) already exist with all needed columns (storage/db.py:36-118); `details_json` absorbs call_key/options. No migration.
- The observer already reads choice_points (tier, self_label_json), latest_values and spend_total/spend_by_week (observer.py:754, 905, 975, 1022, 1041); Phase 4 mostly needs richer rows and the waiting/pause states.
- `sim.replaying` was left as a Phase 4 hook (sim.py:54-56) and recovery replays with full event verification (storage/recovery.py); reuse-first by call_key fits it.
- `rules/turn.py _decide_players` decides players one after another and starts each action at once; concurrency needs the contexts built first. Keeping the sequential path for rule-based-only runs avoids any change to Phase 2-3 event logs.
- Hooked is already computed (rules/wellbeing.py:136 is_hooked, player.hooked) and `[wellbeing] hooked_x/hooked_pain` exist; only `hooked_k` is new.
- Knowledge book exists (world/agents.py KnowledgeEntry; rules/actions/social.py:336 add_knowledge): reflection knowledge notes reuse add_knowledge with source "self".
- SDKs and python-dotenv are already importable (Setup installed them), so no `uv add` should be needed; A checks pyproject lists them.
- Interrupt kinds exist (spoken_to, attacked, hurt, loss_noticed, storm_started, band_changed, player_in_sight, dog_in_sight); "idle" in turn.py is not one of the four triggers and is mapped to "finished".
- AC-23's `new` currently only creates a run at tick 0; a `--ticks` option (and `--fake-ai`) is needed for "runs a game week".

## Risks
- Turn budget: ~19 Work IDs; delegate in slices of 3-4 Work IDs with the Report by turn ~45 (lessons P2/P3).
- Prompt-leak words: "game" may appear in existing sense templates or action text (e.g. hunting); check_clean in tests over a fake week will catch it; coder-b must grep templates.py first.
- Determinism with threads: only generator results are applied, in player_order; DB row ids of ai_calls may differ between runs, so AC-21 compares event logs only.
- A full fake week with 4 AI seats may be slow (embedding + prompts every decision); mark long tests `slow`, use FakeEmbedder.
- Snapshot size: memory streams as text only, capped at stream_max.
- Real SDK request shapes change between versions; adapters are tested against mocked clients using the installed SDK's types where possible; the researcher's notes pick the exact parameters.
