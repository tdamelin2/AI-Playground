## Summary
- New per-tick agent turn on top of the Phase 1 scheduler: `Simulation.run` calls `advance_to` (world jobs) and then `rules.turn.run_turn(world, tick, decide)` every tick. Order inside a turn: bodies -> sight interrupts -> decisions -> resolve actions (rotated player order, clashes by the `clash` stream) -> villagers -> dogs attack -> chat phase -> witnesses.
- State lives in `world/agents.py` (Player, Villager, Body, Inventory, Tool, Structure, ActionState, KnowledgeEntry, HarmRecord) and round-trips in the snapshot (SNAPSHOT_VERSION 3).
- `rules/` (A): body needs, X (concave f + B half-life), feeling bands, every action in `rules/actions/` with durations from balance.toml, tools, fire, buildings, social, harm, belief, land claims, interrupts, the turn. `rules/senses/` (B): Discoverer (sight/hearing/body words/place memory/report templates/witnesses/sight interrupts), chat phase, gossip and scripted lines. `rules/tasks.py`, `rules/landmarks.py` (B).
- `minds/` (B): Controller protocol, 4 rule-based dummy players, scripted scenario players. `measure/report.py` + `main.py report --run` (B). Viewer draws players, villagers, borders and stakes (B).
- Every number in balance.toml/world.toml with a reason comment; AC-29 balance targets checked by `report` on a persisted full-year dummy run.
- Performance budget: headless full year with 4 dummy players + villagers under 5 minutes (Phase 1.5 was 18 s without agents); senses are computed on demand (decisions, harm events), not for every agent every tick.

## Findings
- The engine is event-driven (advance_to skips idle ticks), which made the full year 18 s. Players need every tick, so the per-tick turn must stay cheap: needs on an interval, sight interrupts for 4 players only, sense reports only on decisions, witnesses only for harm records. Budget < 5 min for a dummy year (recorded).
- WorldFrame lives in world/view.py (A's folder); the viewer change is B's. Freeze AgentView in the Contract.
- chats table exists since Phase 1 and nothing writes it; Phase 3's Chats tab needs rows with hearers, so chat_spoken also goes to that table now.
- AC-6 "-10 X" conflicts with respawn restoring needs (X would jump up): defined as X_after = X_before - 10 by setting B at respawn.
- AC-19 vs "build a shrine": building a shrine is a building (costs, structure). Plan: build_shrine = a belief-tagged build; pray/ceremony change nothing but time; offering removes the offered item only; AC-19 is tested on pray/ceremony/offering and on the shrine having no effect beyond its structure.
- assets.toml already has player_1..4, villager_1..6, claim_border_1..4, boundary_stake and markers; no asset changes needed except possibly colours (B).
- Sight/hearing metric is unspecified ("about 7"): Euclidean, no occlusion.
- AC-29 is a tuning target; likely to need a fix round. The report command must make each target a number so the debugger can tune balance.toml rather than code.
- Phase 1.5 suite is 5 min; Phase 2 adds a full-year dummy run (AC-29) and a scripted scenario (AC-30): both `slow`, the persisted year run once per session (module fixture).
