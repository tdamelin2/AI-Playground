# Phase 3: Observer screen, run control and exports | Claude plan
Status: Done | Started: 2026-11-02 15:53 | Finished: 2026-11-02 16:01
Helpers: 2 coders - backend (run control, saving, recovery, measures, export, frame data) and the pygame_gui observer are structurally separate and meet only at a frozen data/controls contract

## Summary
Part A builds everything that is not pygame: a `LiveRun` run controller in storage/ (paced ticks with a per-frame time budget, pause/resume/speed, autosave every `autosave_interval` ticks, keep-awake, spend counter), crash recovery (restore last snapshot, deterministically replay to the end of the stored tail, verify it matches, continue without rewriting), snapshot v4 (graves), new read-only RunDB queries, two small event additions (`helped`, `player_day.villager_loyalty`), `measure/history.py`, `measure/weekly.py`, `measure/export.py`, frame additions (structures, graves, player panels, names) and the CLI (`live`, `export`, `measures`, `--crash-after-tick`, `view` on an in-memory DB copy).
Part B builds `observer/`: an `Observer` window (top bar, map area, right tab panel with the five pygame_gui tabs, monogram font, DPI-aware layout sized from the desktop), map additions (buildings, damaged versions, grave and state markers), tab text built from A's accessors, and the screenshot path. `Viewer` stays usable standalone so Phase 1/1.5/2 viewer tests keep passing.
The observer is read-only: it reads `WorldFrame` and `RunDB` read methods and calls only `controls.toggle_pause()` and `controls.set_speed()`.

- LiveRun (A; `ai_island.storage.run_control`): `LiveRun.open(config, path: Path, seed: int | None, players: str | None, keep_awake: KeepAwake | None = None) -> LiveRun` (creates the run if the db is missing, else recovers); attributes `sim`, `db`, `recovery: RecoveryInfo | None`; `advance(real_seconds: float, budget_seconds: float) -> int` (ticks owed = real_seconds * speed / seconds_per_tick plus carried remainder; runs whole ticks until owed or budget used; returns ticks run; 0 while paused); `run_ticks(n)`; `pause()` (stops after the current tick, flushes and saves a checkpoint, releases keep-awake); `resume()` (re-acquires); `toggle_pause()`; `flush()`; `close()` (save checkpoint, release, close db; safe twice). The live frame loop in cli.py: pump -> advance(dt, frame_tick_budget / fps) -> flush -> draw -> sleep the rest of the frame.
- Autosave (A, in Simulation): with a db attached, `Simulation.run` saves a checkpoint each time world.tick reaches a positive multiple of run.autosave_interval (chunks end on those ticks; chunking never changes events); `sim.last_autosave_tick`. Applies to headless --run, resume and live. Adds no event, draws no RNG.
- Crash recovery (A; `ai_island.storage.recovery`): `recover(db: RunDB, assets=None) -> tuple[Simulation, RecoveryInfo]`, `RecoveryInfo(snapshot_tick, tail_events, end_tick)`. Restore the latest snapshot; tail = events with id > last_event_id (K of them, last tick T_e). If K = 0, attach as already stored. Else run with `sim.replaying = True` until world.tick == T_e, compare the first K regenerated events to the tail (tick, type, payload_json); mismatch raises RecoveryError("replay diverged at event <id>"); then attach with the K events marked stored and `replaying = False`. Phase 4 hook: while `sim.replaying` is True the mind layer must take AI replies from stored ai_calls instead of calling (documented on the attribute). Replaces `_check_no_tail` in headless --run, resume, live and view.
- `--crash-after-tick N` (A; hidden from --help) on headless/resume/live: after tick N the run writes its pending events (no snapshot) and calls os._exit(3), simulating a crash after a database write.
- KeepAwake (A; `ai_island.storage.power`): `KeepAwake(setter: Callable[[int], int] | None = None)`; default setter = ctypes.windll.kernel32.SetThreadExecutionState on win32, a no-op elsewhere; `acquire()` calls setter(0x80000001) (ES_CONTINUOUS | ES_SYSTEM_REQUIRED), `release()` calls setter(0x80000000) (ES_CONTINUOUS); `active: bool`; idempotent; LiveRun acquires on open/resume, releases on pause/close and in a finally/atexit.

Measures: promises_made / promises_kept / promises_broken (player = maker, partner = to); help (helped: player = actor, partner = target, kind); harm (harm: player = actor, partner = victim, kind); villager_deaths / villager_departures (player = leader); villager_loyalty (mean of that week's player_day.villager_loyalty, None when no sample); belief_actions (belief_act, kind). For every week 1..last and every player a total row (partner "", kind "") always exists (0 when nothing happened); partner/kind breakdown rows only when > 0. Example: promise_made(maker player_1, to player_2) at tick 100 and promise_kept(player_1 -> player_2) at tick 10100, week_ticks 10080 -> MeasureRow(1, "promises_made", "player_1", "", "", 1), MeasureRow(1, "promises_made", "player_1", "player_2", "", 1), MeasureRow(2, "promises_kept", "player_1", "", "", 1), and promises_kept week 1 player_1 total 0. CLI `main.py measures --run <run>` prints them as a table.

CLI `main.py export --run <run> [--out <dir>]`, default `runs/<run>/export/`; opens the db read-only; prints each file and row count. Re-reading each file with csv.reader gives COUNT(*) data rows.

## Findings
- Existing: `cli._cmd_view` already has a paced frame loop with sub_tick; it runs up to 5000 ticks per frame at high speed, which breaks "30 fps independent of tick speed" (AC-2). LiveRun.advance must stop on a wall-time budget.
- `Simulation.run` unpaced advances in day chunks and flushes every `event_batch` events; flushes always happen between whole ticks, so a stored tail always ends at a tick boundary. That makes deterministic replay to T_e exact.
- `cli._check_no_tail` refuses runs with a tail ("Crash recovery is not supported until Phase 3"); Phase 3 replaces it with recovery. No test checks that message.
- Snapshot spend_usd is always 0.0 today; `spend` table exists from Phase 1. Run.toml has no spend cap yet.
- No event carries a gift/teach target (`action_finished` has none), and loyalty is never logged, so the help measure and average loyalty need the two small event additions above.
- Villagers die permanently but no grave position is kept; WorldFrame has no structures. Every building sprite and `damaged_<kind>` and `marker_grave` already exist in assets.toml; `ui_*` items and `assets/fonts/monogram/monogram/ttf/monogram.ttf` exist.
- A populated snapshot is ~600 KB of JSON; autosave every 360 ticks is ~224 snapshots (~135 MB) per game year, ~70 MB for the planned 6-8 week run. Acceptable; no compression this phase.
- `view` must stay read-only: running it on a backup copy of the run db in memory lets the tabs show the extra simulated ticks without writing to disk.
- Existing viewer tests construct `Viewer(assets, view, ROOT)` directly; the Observer must compose the Viewer, not replace its API.

## Risks
- pygame_gui text boxes are slow when re-laid every frame: B rebuilds a tab's text only when new rows arrive, and caps rows at tab_max_rows.
- High-DPI: Tim's 3200x2000 screen. The screenshot under the dummy driver uses 1280x800, so the manager also checks the layout maths for 3200x2000 (ui_scale 2, map scale 3).
- Replay divergence if any state escapes the snapshot (controller state, counters): the AC-11 tests compare full event logs; recovery verifies the tail and fails loudly instead of silently forking.
- Test time (17 min already): long runs (pause/resume/crash comparisons, scripted measures run) are marked slow and share module fixtures.
- Turn limits: delegate A in slices (A-01..03, A-04..06, A-07..10) and B in slices (B-01..02, B-03..05).
