## Summary
- The judge runs inside AI runs as a DB-driven annotator after each committed tick: at every hour end (tick % 60 == 0) it labels all unlabelled choice points (full or short), at day ends it writes a daily summary and code+judge flags, at week ends one profile per player. Calls go through the run's CallBroker and SpendLedger (role "judge", player_id None, stable keys), so caps, retries, recording and reuse-after-crash all work as in Phase 4.
- Judge output is stored as judge_labels rows and two new "annotation" event types (judge_summary, judge_flag) appended directly to the DB; recover() ignores annotation types when it compares the replayed tail, and replay never runs the judge (catch-up after attach is idempotent by key).
- A live backend (`run.ai.backend = "live"`) builds real adapters through llm/factory.py and Ollama embeddings; a hard guard (`AI_ISLAND_OFFLINE=1` env, set by tests/conftest) makes every real-client constructor raise. Paid CLI paths need `--max-dollars` and a typed `yes`; `--fake`/`--dry-run` use the fake adapter.
- New measures (stated vs revealed values, hooked vs unhooked "against" shares, Advisor following, superstition events, invented beliefs, weekly value weights with causes) are added to `weekly_measures` (AI runs only) plus `value_changes.csv` in export.
- Offline tools: `calibrate` (sample slow/hooked/fast decisions from a fake 4-seat sim, run on all main and helper roles, adjust thinking along config ladders, cost model, report.md/result.json, `--apply` via tomlkit), `judge-check`, `analyze` (analysis.md + CSVs + tuning proposals from config rules), `launch-check`, `new --profile pilot|launch`.

Keys: label "judge/<level>/<decision_key>", day "judge/day/<d>", profile "judge/profile/<w>/<player_id>". C9 Tools (B). `measure/calibrate.py: run_calibration(config, adapters, max_dollars, out_dir, dry_run) -> CalibrationResult` writes `runs/calibration/report.md` and `result.json` with, per main role: model, version, final thinking settings, mean thinking tokens (Anthropic: output_tokens - ceil(len(reply)/chars_per_token), marked "estimated"), cost per slow decision (noticer+advisor+main), cost per hooked decision; and overall cost per game week, game weeks per $100, reaches week 7 (cap from run.toml / cost per week >= target_week), cheap seat per game week, pilot estimate. Formulas: seat_week = 7*(slow_per_day*cost_slow + hooked_per_day*cost_hooked + fast_per_day*cost_fast) + reflection_cost_factor*cost_main_slow; judge_week = 7*4*(slow_per_day+hooked_per_day)*judge_label + (7+4)*summary_cost_factor*judge_label; week = sum seats + judge_week; cheap seat uses main samples on the helper role; pilot = pilot_weeks*(4*cheap_seat_week + judge_week). Example: cost_slow 0.03, cost_hooked 0.02, cost_fast 0.001, cost_main_slow 0.025 -> seat_week = 7*(0.45+0.10+0.012) + 0.05 = 3.984. Adjust: target = median of the four mean thinking tokens; a role outside target*(1±tolerance) moves one ladder step toward it; repeat up to max_rounds on the roles that moved. Dry run: FakeAdapter(bill=True), all calls in `runs/calibration/calls-<n>.db`. `apply_calibration(models_toml: Path, result)` rewrites thinking and calibration blocks with tomlkit, keeping comments.
`measure/judge_check.py: run_judge_check(config, adapters, max_dollars, out_dir) -> list[(sample, label, cost)]` prints each label and its cost, writes `runs/judge-check/report.md`.
`measure/analyze.py: analyze_run(db_path, config) -> Analysis` writes `runs/<run>/analysis.md` and `runs/<run>/analysis/{deaths,x_by_day,food_short,decisions_by_day,failures,cost_by_week,tuning}.csv`. Metrics: deaths (players, villagers, by cause), X per player per day (mean) and per week, first food-short day per player and number of food-short days, extinction events, decisions per player per game day by trigger (finished, spoken_to, interrupt, check) and by tier (reflex, fast, slow, hooked), refusals and schema failures (ai_calls status + decision_made failure), cost per game week. game_day(tick) = max(0, tick-1)//ticks_per_day + 1. Example: player_1 with 30 decision_made over days 1-2, 12 finished + 18 check -> finished 6.0/day, check 9.0/day.
`measure/tuning.py: proposals(metrics: dict[str, float|None], rules, config) -> list[Proposal{area, key, current, proposed, metric, measured, target, evidence}]`: no proposal when target_min <= measured <= target_max or measured None; number keys: proposed = current*(1+step) for "up" else current*(1-step), ints rounded and changed by at least 1. Example: rule first_food_short_day 8..21, key world.plants.berries.per_home=3, step 0.2, below "up": measured 5 -> proposed 4; measured 14 -> none.
`measure/launch_check.py: launch_checks(root, config_dir) -> list[Check{name, ok, detail}]`: (1) `git status --porcelain -- config` empty (git missing -> fail), (2) run.toml has an explicit spend_cap_usd > 0, (3) run.toml has an explicit integer seed. Prints "[PASS] ..." / "[FAIL] ..." per check; exit 0 only when all pass, else 1.

## Findings
- The judge_labels table exists since Phase 1; the observer already shows the newest label raw as "judge: <json>" (observer.py:764, 955). Phase 5 must render it in words.
- No table fits summaries; events is the only generic append-only table. Putting judge output into world.events would make recovery replay need judge replies at the end of a tail (paused judge -> ReplayMissingError). Writing them as annotations straight to the DB and filtering them in recover() avoids that.
- `AiRun.backend` is `Literal["fake"]` and factory.make_adapter is never called; `_ensure_ai` always uses FakeAdapter and FakeEmbedder. Tim's paid steps need a live path; agents must never reach it.
- Anthropic usage has no thinking-token field (adapters.py:134 thinking_tokens=None); calibration needs an estimate for it.
- `--ai-seats` needs `--players dummy`; the pilot needs 4 seats with cheap=True, which already maps main -> own company helper (ai.py:191).
- value_history cause ids are memory-item ids (Phase 4 known limit); linking value changes to causes needs the texts/ticks stored at reflection time.
- `weekly_measures` and export are pinned by Phase 3 tests (MEASURES set per week/player; exact CSV file set in test_AC14). New AI measures appear only in AI runs; value_changes.csv changes the export file set, so test_AC14 needs the tester's update.
- Phase 4 tests that call `new --ai-seats` (test_p4_llm.py:526, test_p4_run.py:364) stay fake because the CLI default backend is... see Question P5-Q-CLA-01; if the CLI default becomes live they need `--fake`.
- No superstition or new-belief event exists; the judge label carries them.

## Risks
- Real calls by an agent: guard env in tests, `confirm_spend` needs a typed yes (stdin is null for agents), tasks forbid live commands. Coders run only `--fake` / `--dry-run` paths.
- Event-log determinism: annotations are outside world.events, so Phase 1-4 determinism and recovery tests are unaffected; a test must prove recover() still passes with annotations in the tail.
- Suite time: 4-seat fake runs of days/weeks are slow; tester marks them slow and uses `--ticks` overrides in quick tests; one profile-length pilot test marked slow.
- Turn limits: slice coders (A: 01-03, 04-05, 06-08; B: 01+07+08, 05+06, 02-04+09) and the tester in two parts.
- tomlkit is a new dependency; added by A-01 with `uv add tomlkit` so B-04 can use it.
